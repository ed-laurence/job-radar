# Data model (Postgres 16)

Derived from the job-seeker SQLite schema, plus users, the dev board, agent runs, leases, rate limits, web analytics and provider-aware LLM logging. Migrations live in `backend/migrations/` (Alembic). The HTTP shapes are in `api/openapi.yaml`.

## Conventions
- Ids are `uuid` (generated by the `Ids` port). Timestamps are `timestamptz` (UTC, set via the `Clock` port). Every table has `created_at`; mutable tables also have `updated_at`.
- **User-owned** tables (marked **U**) have `user_id uuid not null references users(id)` and row-level security: `ENABLE` + `FORCE ROW LEVEL SECURITY`, with the policy `user_id = current_setting('app.user_id')::uuid` for all commands. The app connects as a non-owner role. Child tables carry their own `user_id` (not only via the parent) so every policy is a single-column check.
- **Shared** tables (marked **S**) hold the dev board, which both accounts see. RLS still requires `app.user_id` to be set (`current_setting('app.user_id', true) is not null`); maintainer-only writes are enforced in the domain service.
- **System** tables (marked **Sys**) are written by the app or jobs only and never returned raw.
- `version int not null default 1`: optimistic concurrency, bumped on every update. `UPDATE … WHERE id = $1 AND version = $2`; zero rows means 409.
- `rank text collate "C" not null`: fractional index (base-62 key). Ordering is by `(rank, id)`.
- Soft delete: `deleted_at timestamptz`. Default queries and partial indexes filter `deleted_at is null`.
- Fixed vocabularies are `text` with a `CHECK` constraint matching the spec enums. No free-text JSON where a column will do; `jsonb` only for genuinely nested data.

|---|---|---|

## Platform (all **Sys**)

| table | columns and notes |
|---|---|
| `rate_limit_buckets` | PK `(key, tier)` where `key` is `user:<uuid>` or `ip:<hmac>` (salted hash, never the raw IP); `tokens numeric`, `refilled_at`. Updated with one `UPDATE … RETURNING` per request. Tiers match the spec's `x-rate-limit-tier`. |
| `web_events` | `at`, `day date`, `session_id` (browser-generated, rotated daily), `role_tag` (`maintainer`/`user`, the only identity stored), `type` (`page_view`/`product`/`web_vital`), `route` (template only), `name`, `metric`, `value double precision`, `rating`. No user id, IP, user agent or cookie. Partitioned by month; the rollup job drops rows older than 90 days. |
| `job_runs` | Replaces `scan_runs`: `job` (`feed-replay`, `digest`, `rollup`, `watchdog`, `evals`), `started_at`, `finished_at`, `ok`, `items_seen`, `items_new`, `error_code`. |
| `app_state` | PK `key`, `value jsonb`: circuit breakers and other global key/value state (was `kv`). |

## Dropped from v1
- `scan_runs` (scraping is replaced by feed replay over seed data) → `job_runs`.
- The `kv` table's per-user keys → `user_settings`; global keys → `app_state`.
- `role_chat_files.data` BLOB → GCS object keys.
